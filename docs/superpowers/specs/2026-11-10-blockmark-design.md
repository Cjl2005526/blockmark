# 色块标注（BlockMark）设计文档

日期：2026-11-10
状态：待用户审阅

## 1. 背景与目标

用 AI 改图时，光靠文字描述很难说清"改哪里、别动哪里"。用户需要在手机上快速把**要修改的区域**框出来，导出一张带半透明色块和编号的图片，交给会看图的 AI（多模态模型 / 图生图工具）作为区域提示。

一句话：**选图 → 框区域 → 导出标注图**。

成功的样子：在手机上单手两分钟内框出 3 个区域并导出一张 PNG，打开后色块位置与原图严丝合缝，编号清晰，直接发给 AI 即可。

## 2. 用户已确认的决策

| 问题 | 结论 |
| --- | --- |
| 用途 | 让 AI 生图/改图时理解"需要修改的区域" |
| 产品边界 | 只做标注与导出，**不调用任何 AI 接口** |
| 导出形态 | 半透明色块 + 编号标注图（PNG），不导出黑白遮罩 |
| 标注规模 | 一次 2～5 个区域，编号区分，图上不写说明文字 |
| 形状 | 矩形、圆形、三角形三种；三种都要能横向/纵向单独拉伸 |
| 平台 | 网页版（PWA），手机浏览器打开即用，可添加到主屏幕 |
| 后续扩展 | 结构上把渲染与导出分层，给黑白遮罩导出、AI 接口留位置；v1 不实现其界面 |

## 3. 非目标（v1 明确不做）

- 黑白遮罩 / 蒙版导出、JSON 坐标导出
- 调用任何 AI 生成接口
- 手绘、套索、自由曲线
- 形状旋转、图上文字说明
- 自动保存草稿、账号、云同步、多图批量
- 真正的原生安装包（上架时再用 Capacitor 包壳）

## 4. 用户流程

1. 打开页面（首次显示空状态：大按钮"选择图片"，附"拍照"入口）
2. 选图 → 图片按 `contain` 铺满画布区（黑色底，不裁切）
3. 点底部 `▭ ◯ △` 任一按钮 → 在画面中央生成默认大小的色块，自动选中
4. 拖动色块移动；拖四边单向拉伸；拖四角自由变形；直至贴合目标区域
5. 点色板换色；点 `↶ ↷` 撤销重做；点 `🗑` 删除
6. 点右上角"导出" → 生成原图分辨率的 PNG → 系统分享面板（iOS）或直接下载（安卓/桌面）
7. 可"重新选图"（已有标注时二次确认）

## 5. 界面

自上而下四段，全部固定高度布局，画布区自适应：

```
┌───────────────────────────┐
│ 状态栏（安全区）            │
│ ‹       3 个标注       导出 │  ← 顶栏 44px（‹ = 重新选图）
├───────────────────────────┤
│                           │
│        图片 + 色块         │  ← 画布区 flex:1，黑底
│                           │
├───────────────────────────┤
│  ▭   ◯   △      ↶ ↷ 🗑    │  ← 形状/操作行 40px
│  ● ● ● ● ● ●   透明度 36%  │  ← 色板行 36px
└───────────────────────────┘
```

- 尺寸全部用 `env(safe-area-inset-*)` 避让刘海与手势条
- 竖屏为主；横屏、平板、桌面浏览器同样可用（画布区自适应）
- 选中态：白色虚线边框 + 8 个 12px 见方的白色控制点（蓝描边），命中区 44×44px
- 未选中时色板行置灰不可点，提示"选中色块后可改色"
- 撤销 / 重做按钮在对应栈为空时置灰
- 空状态：画布区居中显示"选择图片"大按钮 + "拍照"次按钮，工具条隐藏
- 图片解码中：画布区显示转圈，顶栏标题显示"3 个标注"（实时随数量更新）

## 6. 形状与几何

**统一模型**：所有形状都用一个外接矩形（bbox）定义，形状类型只决定在 bbox 内如何绘制，因此三种形状天然共享同一套移动/拉伸逻辑：

| 类型 | bbox 内的绘制 |
| --- | --- |
| `rect` 矩形 | 填满 bbox |
| `ellipse` 圆形 | 内切椭圆（bbox 为正方形时是正圆） |
| `triangle` 三角形 | 等腰三角形：顶点在 bbox 顶边中点，底边贴 bbox 底边 |

```js
// 坐标全部是相对图片显示区域的比例值 0..1
{ id: "s_1", type: "rect" | "ellipse" | "triangle",
  x: 0.35, y: 0.30, w: 0.30, h: 0.30,
  color: "#FF3B30" }
```

- 新建默认：`w = h = 0.30`，居中放置（`x = y = 0.35`）
- 约束：`x, y ≥ 0`；`x + w ≤ 1`；`y + h ≤ 1`；最小边 28 CSS px（手势过程中先按像素算，落库时换算成当前显示区域的比例值）
- 拉伸语义：
  - 拖 4 条边：只改一个维度（横向或纵向单独拉伸）
  - 拖 4 个角：同时改宽高（自由变形）
  - 桌面按住 `Shift` 拖角：锁定宽高比
- 拖动整体：超出图片边界的部分被夹住，不产生负坐标
- 点选与拖动的区分：位移超过 4 CSS px 才认定为拖动，否则算点选（避免手抖导致误移）
- 层级：后添加的在上面（数组顺序即绘制顺序）；编号 = 数组下标 + 1
- 命中：交给 SVG 元素的绘制顺序，最上层先响应；矩形命中整个 bbox，圆与三角形命中形状本身（bbox 的空白角落点不到）

## 7. 颜色与透明度

6 色固定色板，新色块按 `数组下标 % 6` 自动取色，手动可改：

| 序号 | 颜色 | 色值 |
| --- | --- | --- |
| 1 | 红 | `#FF3B30` |
| 2 | 蓝 | `#0A84FF` |
| 3 | 绿 | `#34C759` |
| 4 | 橙 | `#FF9F0A` |
| 5 | 紫 | `#BF5AF2` |
| 6 | 白 | `#FFFFFF` |

- 填充透明度固定 **0.36**（既能看出区域，又能看清底图内容）
- 描边用同色不透明版本，屏幕 2 CSS px；导出时按输出尺寸换算（见 §9）
- **白色色块**在浅色照片上会消失，因此所有色块统一带 1px `rgba(0,0,0,.35)` 的内侧衬线，白色尤其依赖它保持可见

## 8. 编号徽标

- 位置：色块 bbox 的左上角，圆形徽标圆心与该角重合，随后夹在图片范围内（留出半径边距）
- 屏幕：直径 17px，10px 加粗字
- 导出：半径 `r = clamp(0.022 × min(W, H), 10, 64)` 像素，字号 `1.1r` 加粗
- 文字颜色按底色亮度自动选：红/蓝/绿/紫用白字，橙/白用接近黑的 `#1D1D1F`（`#FFFFFF` 白底白字会看不清）
- 删除中间的色块后，后续编号自动前移，保持 1..n 连续

## 9. 导出（核心）

- 输出尺寸 = **原图像素尺寸**；若 `W×H > 16,777,216` 或 `max(W,H) > 4096`，按 `k = min(1, 4096 / max(W,H), sqrt(16777216 / (W×H)))` 缩放后取整，并 toast 提示"已按 4096 边长导出"
- 用离屏 `<canvas>` 重绘：`drawImage` 原图 → 逐形状画填充（`rgba(color, 0.36)`）→ 描边 → 编号徽标
- 描边宽度：`max(2, 0.0035 × min(W, H))`
- 徽标：实心圆 + 加粗数字，居中，字色规则同 §8
- 方向：直接绘制页面上的 `<img>`，EXIF 旋转由浏览器处理（现代浏览器绘制时已转正），不另行处理
- 文件名：`标注_YYYYMMDD-HHmm.png`
- 保存路径：`navigator.canShare({files})` 可用则调分享面板（iOS 上用户选"存储图像"），否则 `<a download>` 下载
- 导出过程用 `toBlob`，失败（返回 null / 抛错）→ toast"导出失败，请重试或换张图"

## 10. 状态与撤销

- 状态：`{ image, shapes: [], selectedId, undoStack, redoStack }`
- 每次**结构性变更**入栈（增、删、改色、一次手势结束时的位置/尺寸变化），最多 50 步
- 手势过程中不入栈，`pointerup` 时若与手势前不一致才入栈（避免拖动产生几十条记录）
- 撤销/重做同时恢复 `selectedId`；新操作清空 redo 栈
- 换图：清空形状与历史（有标注时先确认）

## 11. 错误处理

| 情况 | 处理 |
| --- | --- |
| 选了非图片文件 | toast "只支持图片文件" |
| 图片解码失败（如某些 HEIC） | toast "这张图格式不支持，试试另存为 JPG" |
| 图片过大导致解码内存不足 | 捕获 `img.onerror`，提示换小图 |
| 导出失败 | toast "导出失败，请重试"；不破坏当前编辑状态 |
| 分享面板被取消（`AbortError`） | 静默忽略，不报错 |
| 未选图就点导出 | 按钮禁用 |
| 有标注时刷新/关闭 | `beforeunload` 弹系统确认 |

## 12. 技术方案

- **零依赖**：原生 ES 模块 + 原生 DOM/SVG，无框架、无构建、无 npm 依赖；`node --test` 跑单元测试
- **目录结构**

```
blockmark/
├── index.html            页面骨架
├── manifest.webmanifest  PWA 清单
├── sw.js                 离线缓存（app shell，版本号常量）
├── server.mjs            零依赖静态服务器，打印本机 + 局域网地址
├── icons/                192 / 512 / apple-touch-icon 180
├── src/
│   ├── main.js           装配、生命周期、换图
│   ├── shapes.js         纯几何：创建、命中、移动/拉伸约束（可单测）
│   ├── state.js          状态、编号、历史（可单测）
│   ├── view.js           图片与 SVG 渲染、选中框、控制点定位
│   ├── gestures.js       指针状态机（移动 / 8 向拉伸 / 点选）
│   ├── export.js         导出：尺寸决策、绘制、分享/下载
│   ├── ui.js             工具栏、色板、空状态、toast、确认
│   └── styles.css
└── tests/
    ├── shapes.test.mjs
    ├── state.test.mjs
    └── export.test.mjs
```

- **渲染**：`<img>` 铺底；覆盖一层 `svg`（`viewBox="0 0 100 100"`、`preserveAspectRatio="none"`、`vector-effect="non-scaling-stroke"`），每个形状一个元素；控制点层用绝对定位 DOM，用百分比定位到 bbox 的 8 个点
- **指针**：Pointer Events + `setPointerCapture`；`touch-action: none`；只跟踪第一个触点（忽略多指，避免误触）
- **视口**：`user-scalable=no` 防止双击缩放；按钮 `touch-action: manipulation`
- **兼容**：iOS Safari 16+、Android Chrome 100+、桌面 Chrome/Edge/Safari

## 13. 测试与验收

**单元测试（node:test）**
- `shapes`：8 向拉伸的边界夹取、最小尺寸、四角与四边的语义、负坐标不出现
- `state`：新增自动选中、删除后编号连续、撤销/重做 20 步后形状与选中态一致、redo 被新操作清空
- `export`：`computeOutputSize` 的 4096/1600 万像素降级、徽标夹取、描边宽度公式

**手工验收**
1. 桌面 Chrome：选图 → 三种形状各一 → 每块都做一次单向拉伸与一次自由变形 → 导出 → 用图片查看器核对位置
2. 手机（iOS Safari / Android Chrome）：全流程单手完成，导出图能在相册里打开
3. 删除 2 号 → 原 3 号变 2 号；撤销后恢复
4. 横竖屏切换后色块不跑位
5. 添加到主屏幕 → 断网 → 能打开并编辑
